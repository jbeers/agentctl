# agentctl v0.1.0-alpha.2

## Behavior changes

- New bundles use the public Linux `amd64` Hermes appliance at `ghcr.io/jbeers/agentctl`, pinned to an immutable platform digest.
- The normal runtime pull is anonymous and needs no GHCR credential.
- Runtime publication and the downloaded CLI now originate from the canonical `agentctl` repository.

## Security-relevant changes

- The runtime package has no `latest` tag; immutable version and source-revision tags trace it to canonical source.
- Publication includes SBOM and SLSA provenance attestations and starts a real Hermes gateway before accepting the image contract.
- Published-image verification pulls anonymously by digest and checks Hermes, GitHub CLI, Podman, `podman-compose`, `/workdir`, and socket environment behavior.
- CI now propagates TestBox failures as a failing process status rather than trusting the runner's zero exit status.

## Known limitations

- Linux `amd64` remains the only supported operator and runtime target.
- DigitalOcean, Hermes, Tailscale, rootless Podman, and explicit version 2 bundles remain the supported product boundary.
- The clean-room first-agent guide and documentation website are separate roadmap slices.

## Required operator action

- Verify the executable SHA-256 checksum before upgrading.
- Existing bundles remain valid and are not rewritten automatically. A bundle that explicitly names an older runtime keeps that choice; replace `runtime.image` with the supported digest or pass an explicit `--runtime-image` override to upgrade it.
- Run `agent inspect` before `agent up`. Runtime reconciliation replaces the Hermes container and retains `/opt/data`; `/workdir` remains disposable and is lost with `down` or a cold rebuild.
- Private immutable image overrides remain supported. Supply a registry token only when that selected image requires one.
