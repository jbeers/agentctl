# agentctl v0.1.0-alpha.3

## Behavior changes

- `agentctl docs` opens the canonical documentation website without requiring a bundle.
- `agent rotate` replaces a Tailscale enrollment key, optional registry token, or Hermes dashboard password through a write-only workflow. Registry authentication can also be removed explicitly.
- `agent export` creates a validated portable mode-`0600` archive of ready `/opt/data` state and restores Hermes health before ordinary success.
- `agent purge` provides guarded, irreversible deletion of one exact detached retained volume after `down`.
- Provider-volume inspection accepts current `doctl` GiB size rendering while preserving exact region and configured-size checks.
- `agent status --json` emits schema version 1 with stable ordered product layers while preserving ready-only exit `0` semantics. Human text remains the default.
- Existing version 2 bundles remain valid. No bundle migration or automatic mutation is introduced.

## Security-relevant changes

- Rotation receives replacement values only through hidden confirmed prompts and SOPS standard input. Atomic publication preserves every unselected public and encrypted value; no secret-reading command was added.
- Export requires a fully ready exact appliance, cleanly stops and restarts Hermes, transfers only over private SSH, applies the existing archive validator to exact received bytes, and publishes atomically without printing archive paths or contents.
- Purge has no user-facing force bypass. It requires case-sensitive agent-name confirmation and repeats compute, volume, region, size, attachment, provider-health, and exact-ID checks immediately before deletion.
- JSON status excludes raw provider objects and identifiers, public IPv4, command stderr, private-key paths, credentials, payloads, environment content, and endpoint bodies. Process diagnostics remain separate on stderr.
- State archives remain secret-bearing even at mode `0600`; the retained provider volume remains working storage rather than an independent backup.

## Runtime compatibility

The supported runtime is unchanged from alpha.2 and remains pinned to:

```text
ghcr.io/jbeers/agentctl@sha256:28b6b1715c7d55ba50fda783c49d40030ce10a3e901bd7bd5eec2c812621053f
```

No `latest` tag or private registry token is required for the default image.

## Known limitations

- Linux `amd64`, DigitalOcean, Ubuntu 24.04, Tailscale private access, Hermes, rootless Podman, and explicit version 2 bundles remain the supported boundary.
- Export is deliberate local point-in-time backup, not a schedule, remote backup destination, provider snapshot, or `/workdir` backup.
- Purge cannot verify that a backup exists and intentionally refuses attached, ambiguous, changed, mismatched, or indeterminate provider state.
- There is no idle-shutdown guarantee, hosted control plane, public ingress, second provider, package-manager installation, or third-party security-audit claim.
- This remains a prerelease public alpha. Only the latest alpha is supported.

## Required operator action

- Verify the executable SHA-256 checksum and reported source revision before upgrading.
- Run `agent inspect` and `agent doctor` with each intended explicit bundle before mutation.
- Read [credential rotation](../credential-rotation.md), [state export](../archives.md), and [guarded purge](../purge.md) before using day-two commands.
- Export state while the appliance is ready and before `down` when a portable backup is needed. Protect the resulting archive as credential-bearing material.
- Keep using `down` for normal teardown; it still retains `/opt/data`. Run purge only after compute is absent and only when permanent state deletion is intended.
- Consumers of status JSON must check `schemaVersion`, parse the documented product vocabulary, and preserve the command exit code rather than treating valid JSON as readiness.
